# 审计底稿可复算件抽取（audit-extract）

结项时从共用底稿中摘出可单独复算的审计件的 Web 工具：上传 XLSX，填写指标格与禁发区域，
逐层追溯复算所需单元格，通过后下载只包含指标及依赖的新工作簿，行列随新布局压缩、
引用（含跨表）同步改写并经独立复算核对。

## 启动方式（Docker Compose）

```bash
docker compose up --build
# 浏览器访问 http://localhost:8000
```

容器内 gunicorn 监听 8000；上传底稿、每次分析的产物与持久化 `SECRET_KEY` 均保存在
命名卷 `audit-instance`（挂载到 `/app/instance`）中，默认保留 7 天。
生产环境请通过环境变量覆盖 `SECRET_KEY`；未设置时首次启动自动生成并持久化到实例目录，
保证多 worker 与服务重启后会话、结果页链接继续有效。

本地直接运行（Python 3.11）：

```bash
pip install -r requirements.txt
python wsgi.py            # 开发服务器
# 或 gunicorn --bind 0.0.0.0:8000 wsgi:app
```

## 操作流程

1. **上传**：仅 `.xlsx`，≤ 6 张表，每表 ≤ 200 行 × 40 列，文件 ≤ 8 MB。
2. **配置**：选择工作表并填写指标格（`B5` 或 `$C$12`）与禁发区域（单格或 `A1:D10` 矩形），
   行可动态增删；地址均带所属表名提交。
3. **追溯**：从每个指标格按公式依赖逐层 DFS 追溯。
4. **结果**：
   - 命中禁发格、循环引用、不支持内容、越界/文本引用时，列出**指标原地址、错误类型、
     说明和完整出错引用链**，整次不提供下载；
   - 全部通过则展示指标新旧地址对照、复算核对结果、各表保留的行列，并提供下载。

## 多次与交错分析的隔离规则

同一份底稿可以反复选择不同指标、多次生成审计件，每次点击“追溯并生成”都是一次**独立提交**：

- 每次提交获得随机、不可猜的 `submission_id`，产物只写入
  `runs/<run_id>/submissions/<submission_id>/audit_extract.xlsx`，互不覆盖、互不删除；
- 结果页地址为 `/result/<submission_id>`、下载地址为 `/download/<submission_id>`，
  页面上的地址对照、复算值与下载文件严格对应**同一次提交**；
- 下载仅在该次提交复算通过（`meta.status=ok`）且产物存在时开放；复算/追溯失败时
  结果页展示本次原因，下载返回 404，且不会删除或影响其它已通过提交的文件；
- 结果页与下载**不依赖会话 Cookie**：只要上传仍在保留期内，无论另一次分析正在进行、
  通过还是失败，已通过的链接都能下载原来那份文件，**服务重启后同样有效**；
- 提交 ID 含十六进制与长度白名单校验，伪造或过期 ID 一律 404。

## 支持的公式子集

- 数值与四则运算（`+ - * /`、括号、一元负号）；
- 工作簿内 A1 单格引用，含绝对地址（`$A$1`、`$A1`、`A$1`）与跨表引用（`表名!A1`，
  含空格/连字符的表名自动加引号）；
- 对**单个矩形区域**的 `SUM`（`SUM(A1:C10)`，单格 `SUM(A1)` 也可）；
- SUM 区域内的**空格同样计为引用位置**，随件保留；区域内文本按 Excel 语义求和时忽略；
- 其余函数（IF、VLOOKUP…）、字符串运算、外部工作簿引用、数组公式等一律报“不支持内容”。

## 新文件规则

- 只写指标格与追溯所需单元格；每张表删除用不到的行与列（连续压缩到左上角）；
- 单格引用与 SUM 区域端点按新行列映射改写，绝对/相对标记与跨表前缀保留；
- 合并单元格整体保留并按新坐标重建；保留单元格的数字格式、行高列宽；
- 无任何所需单元格的表整表删除；
- 工作簿设置 `fullCalcOnLoad`，用 Excel/WPS 打开即自动重算；
- 下载前用**内置独立求值器**分别复算原工作簿与新工作簿的每个指标，数值不一致或
  除零等情况阻止下载（产物同时删除）。

覆盖：公式解析/反解析与绝对地址、不支持写法拒绝、多层追溯与层数、禁发引用链、

多指标布局、上传限制、完整 Web 流程（含错误时下载 404），以及
`tests/test_submission_isolation.py` 中针对同一底稿**先后/交错提交**的回归：
两份审计件各自独立、失败提交不删他人文件、复算失败展示原因并阻断下载、

## 目录结构

```
app/
  __init__.py          # Flask 路由、run/submission 两级存储与下载鉴权
  engine/
    formula.py         # 词法/语法解析、AST、按新布局反解析
    evaluator.py       # 独立求值器（复算核对）
    model.py           # openpyxl 只读模型、维度与合并单元格
    tracer.py          # 迭代 DFS 依赖追溯、禁发/循环/不支持内容诊断
    extractor.py       # 新工作簿生成、引用改写、复算核对
tests/                 # pytest 自测与隔离模式入口
Dockerfile, docker-compose.yml, wsgi.py, requirements.txt
```

实例目录（卷 `audit-instance`）布局：

```
instance/
  secret_key                          # 持久化的会话密钥（无环境变量时自动生成）
  runs/<run_id>/
    source.xlsx                       # 本次上传的底稿
    submissions/<submission_id>/
      trace.json                      # 本次追溯结果与出错链
      meta.json                       # 本次状态 ok/trace_error/verify_error 与复算数据
      audit_extract.xlsx              # 仅复算通过时存在，只属于本次提交
```

## 已实现 / 已验证 / 未完成

**已实现**：上述全部规则与页面；每次分析独立成“提交”，结果页/下载按提交 ID 寻址、
复算通过才开放下载；多 worker 与重启后链接持久有效；Docker Compose 启动、会话隔离与
过期清理、独立复算核对与失败阻断下载。

**已验证**：21 项 pytest 全过；并用 2 worker 的 gunicorn 做了真实 HTTP 端到端验证——
上传→先后/交错（含 12 并发客户端）多指标分析→结果页与下载件逐次对应、
除零/禁发/表单校验失败均阻断且不影响已通过件、重启后全新无 Cookie 客户端凭旧链接
下载到字节一致的原文件、伪造 ID 与无 ID 旧入口均 404。
本环境无 Docker 守护进程，镜像构建未在本机执行（Dockerfile/compose 仅静态校验）。

**未完成/已知边界**：
- 本环境未安装 LibreOffice/Excel，未做真实表格软件的重算验证；已通过内置求值器双侧复算，
  并设置 `fullCalcOnLoad` 保证打开时重算；
- 图表、数据透视、条件格式等非单元格内容不迁移（仅迁移值、公式、合并区域、基础格式与行列尺寸）；
- 不支持共享公式/数组公式之外的动态数组、表格结构化引用、命名区域与外部链接（按不支持内容报错）；
- 分析为同步处理，请求期间不展示“进行中”进度页；独立提交目录已保证并发请求互不串件，
  中断的提交只留下不含产物的失败目录，会随过期清理回收。
